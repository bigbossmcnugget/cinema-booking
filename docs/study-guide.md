# Разбор проекта Cinema booking для защиты

Учебное пособие по текущей версии сайта Lumen Cinema

Этот документ нужен, чтобы разобраться в проекте, показать работающий сценарий и отвечать на вопросы преподавателя своими словами. Главный материал для изучения — каталог, состояния страницы, выбор мест и серверная запись бронирования. Учить наизусть весь файл страницы и внутренности библиотек не нужно.

Версия на 27 октября 2026 года. Основной репозиторий: https://github.com/bigbossmcnugget/cinema-booking. Рабочая папка называется `outputs/cinema-booking`. В соседней папке `outputs/lumen-kino` осталась предыдущая версия; для подготовки открывай именно новый проект.

## 1 Что именно показывает проект

Сайт решает одну задачу: посетитель выбирает фильм, дату и сеанс, отмечает свободные места и оформляет гостевую бронь. Каталог содержит три фильма: Batman 1989 года, The Lego Movie 2014 года и Superman 1978 года. Постеры скачаны в папку проекта, поэтому после загрузки приложения изображения не требуют запроса к Wikipedia.

На главной странице есть переключение EN, RU и ET, фильтры по жанру и поиск. По кнопке времени открывается схема из шести рядов по десять мест. После выбора мест открывается простая белая форма с именем и email. При успешном сохранении появляется номер брони. Регистрации и входа в аккаунт нет.

Цены, сеансы и доступность субтитров — демонстрационные данные. Это не действующая касса: деньги не списываются, письмо на email не отправляется. Поле email пока сохраняется как контактная информация брони. Отсутствие регистрации не означает, что поле email — это вход в аккаунт.

На защите можно сказать: «Мы показываем прототип бронирования кинотеатра. Пользователь проходит путь от выбора фильма до номера брони без регистрации. Оплата и отправка билетов — отдельные будущие задачи». Эту фразу стоит понимать, а не читать дословно.

Что показать первым: главную страницу, один фильтр, описание фильма, схему мест, изменение суммы и сохранённую бронь. Не начинай с кода или списка используемых пакетов: сначала преподаватель должен увидеть пользу для посетителя.

## 2 Как запустить правильную версию

В терминале нужно находиться в папке, где лежит `package.json`. Ошибка «No package.json found» обычно означает неправильную папку, а не проблему React.

```sh
cd /Users/jegorkerimov/Documents/Codex/2026-09-04
cd https-www-apollokino-ee-rus-https/outputs/cinema-booking
npm ci
npm run dev
```

Две команды `cd` по очереди открывают рабочую папку и сам проект. Можно также открыть терминал прямо из папки проекта. Команда `npm ci` ставит версии из `package-lock.json`; её достаточно выполнить после скачивания проекта или изменения зависимостей. Для каждого обычного запуска повторная установка не нужна.

Открой `http://127.0.0.1:3000/`. Сервер должен оставаться работающим в терминале. Закрытие процесса прекращает доступ к локальному сайту. Другой человек на другом компьютере не сможет открыть свой `localhost` и увидеть твой проект: адрес относится к его компьютеру.

```sh
npm run build
./node_modules/.bin/tsc --noEmit --incremental false
git status
```

Первая команда проверяет сборку приложения. Вторая отдельно проверяет типы TypeScript без создания JavaScript-файлов. Третья показывает изменения Git. Успешная сборка сама по себе не доказывает, что пользовательский сценарий работает: бронирование нужно проверить в браузере.

Если порт 3000 занят, сначала посмотри, какой процесс там запущен. Не запускай подряд несколько копий и не удаляй базу ради перезапуска. На демонстрации полезно заранее выбрать свободное тестовое место: предыдущая бронь сохраняется и после обновления страницы.

## 4 Как связаны браузер сервер и база

У проекта три уровня. Браузер рисует React-интерфейс и хранит временный выбор пользователя. Серверные обработчики принимают HTTP-запросы, проверяют данные и выполняют SQL. База хранит подтверждённые брони и занятые места.

```text
Кнопка сеанса
  openBooking
  GET /api/bookings?showtimeKey=...
  SELECT мест из booking_seats
  схема свободных и занятых мест

Кнопка подтверждения
  submitBooking
  POST /api/bookings
  проверки и INSERT в базу
  номер брони на экране
```

Каталог на главной берётся напрямую из `lib/catalog.ts`. Он не загружается через `/api/catalog`. Этот дополнительный endpoint существует, но не является источником текущего списка в React. Это важная разница, если преподаватель попросит показать сетевые запросы.

Для базы используется Cloudflare D1, совместимая с SQLite. Во время локального запуска среда Cloudflare эмулирует её на компьютере. Supabase для текущей версии не нужен: ни регистрация, ни удалённая Supabase-база здесь не участвуют.

Браузер не должен выполнять SQL сам. Он отправляет данные через `fetch`, а сервер решает, можно ли создать бронь. Например, красная кнопка места в интерфейсе — только отображение выбранного состояния. Место становится занятым в базе лишь после успешного POST.

Проверь понимание: если обновить страницу до подтверждения, выбранные места потеряются; если обновить после успешной записи, занятые места будут загружены из базы. Разница объясняется тем, какие данные находятся только в React, а какие сохранены сервером.

## 5 TypeScript и React которые нужно знать

TypeScript добавляет проверку типов поверх JavaScript. Файлы `.ts` содержат обычную логику, а `.tsx` позволяют писать JSX — описание интерфейса внутри TypeScript. JSX в итоге превращается в вызовы JavaScript, а не отправляется в браузер как отдельный язык.

```ts
export type Locale = 'en' | 'ru' | 'et';
export type GenreKey = 'superhero' | 'family';
const [selectedSeats, setSelectedSeats] = useState<string[]>([]);
```

`Locale` разрешает только три значения. `string[]` означает массив строк, например `['A1', 'A2']`. Попытку передать число вместо массива компилятор может обнаружить до запуска.

React-компонент — функция, которая возвращает JSX. Когда состояние меняется через setter, React заново вычисляет описание интерфейса. В обычном сценарии не нужно вручную искать кнопку и менять её цвет через DOM.

`useState` хранит изменяемые значения. `useEffect` запускает работу после отображения, например проверку `/api/health` и чтение языка из `localStorage`. `useMemo` вычисляет производное значение при изменении зависимостей. В данном маленьком каталоге он не необходим для скорости; он помогает явно показать, от чего зависит результат фильтра.

В начале `app/page.tsx` стоит `'use client'`. Это нужно для состояний, событий и браузерных API. Серверные `route.ts` работают отдельно и не получают доступ к React-состояниям страницы.

Тип `BookingInput` на сервере не проверяет реальный JSON автоматически. TypeScript исчезает при выполнении, поэтому условия `if`, регулярные выражения и проверки базы всё равно нужны. Хороший ответ на вопрос «зачем проверки, если есть TypeScript»: «Типы помогают при разработке, но внешний HTTP-запрос может содержать любые данные».

## 6 Каталог фильмов и переводы

Открой `lib/catalog.ts`. Тип `Movie` описывает структуру одного фильма: постоянный `id`, название, постер, время сеансов, жанры, цену и переводы. Массив `movies` содержит три таких объекта. Путь изображения начинается с `/images/`, потому что содержимое `public` доступно от корня сайта.

```ts
id: 'batman-1989',
title: 'Batman',
image: '/images/batman-1989.jpg',
times: ['17:00', '19:30'],
genre: ['superhero'],
price: 7,
```

`id` используют как устойчивый ключ, а заголовок показывают человеку. Если перевести Batman как «Бэтмен», идентификатор остаётся прежним. Поэтому язык интерфейса не должен создавать новый набор бронирований для того же сеанса.

`getMovieCopy(movie, locale)` возвращает английские поля самого объекта либо вложенный перевод для RU или ET. Подписи кнопок берутся из другого файла — `lib/ui-copy.ts`. Там находятся `continue`, `name`, `emailLabel` и другие одинаково называемые ключи.

Важная серверная функция — `getMoviePriceCents`. Она находит фильм по идентификатору или названию и переводит цену в целые центы через `Math.round(movie.price * 100)`. Она используется при создании брони: сервер не принимает присланную клиентом итоговую сумму как истину.

Чтобы добавить четвёртый фильм, создай полный объект с уникальным `id`, положи постер в `public/images`, укажи цену, времена и оба перевода. Недостаточно поменять только название на карточке: описание, картинка и серверная цена должны соответствовать одному объекту.

Упражнение: найди цену «Лего Фильма», мысленно рассчитай стоимость двух мест и покажи соответствующий объект преподавателю. Для текущих данных ответ — 12 евро, сервер хранит 1200 центов.

## 7 Фильтрация поиск и отрисовка карточек

В `app/page.tsx` найди `visibleMovies`. Фильтрация строит новый массив, не меняя исходный каталог. При значении `all` проходят все фильмы; иначе проверяется наличие выбранного жанра.

```ts
movies.filter((movie) =>
  activeGenre === 'all' || movie.genre.includes(activeGenre)
)
```

`filter` решает, какие объекты оставить. `map` решает, какой JSX нарисовать для каждого объекта. Поэтому внизу используется `visibleMovies.map(...)`, а каждому `<article>` передаётся `key={movie.id}`. React использует ключи, чтобы сопоставлять элементы списка при обновлениях.

Поиск выполняется в `searchResults`. Строка запроса очищается через `trim()`, затем приводится к нижнему регистру. Название, метаданные и описание фильма тоже приводятся к нижнему регистру. `includes(normalized)` проверяет совпадение части строки.

```ts
const normalized = query.trim().toLowerCase();
const copy = getMovieCopy(movie, locale);
```

Поиск учитывает выбранный язык: при RU сравниваются русские заголовки и описания. Это не полнотекстовая поисковая система и не запрос к базе. Английское слово может не найти русское название, если его нет в выбранном тексте. На пустой запрос показываются первые фильмы каталога.

Фильтр жанра и окно поиска работают отдельно. Изменение фильтра меняет основной список; поиск открывает собственный список результатов. Не обещай, что фильтры объединяются в один сложный поисковый запрос: такого поведения сейчас нет.

Покажи в браузере «Для семьи» — должен остаться «Лего Фильм». Затем сбрось фильтр, открой поиск и введи часть названия. Для проверки пустого результата введи строку, которой нет ни в названии, ни в описании.

## 8 Какие состояния страницы отвечают за бронирование

| Состояние | Пример | Что изменяет |
| --- | --- | --- |
| `bookingMovie` | Объект Batman или `null` | Какой фильм бронируем и открыто ли окно |
| `bookingTime` | `17:00` | Выбранное время |
| `bookingStep` | `seats`, `checkout`, `success` | Какой экран показать |
| `selectedSeats` | `['A1', 'A2']` | Временный выбор посетителя |
| `unavailableSeats` | `['A3', 'B7']` | Какие кнопки недоступны |
| `seatsLoading` | `true` или `false` | Идёт ли загрузка схемы |
| `bookingSubmitting` | `true` или `false` | Идёт ли отправка формы |
| `bookingError` | Текст либо пустая строка | Какую ошибку показать |
| `confirmationId` | `LUM-...` | Номер сохранённой брони |

Экран выбирается условием, например `bookingMovie && bookingStep === 'checkout'`. Пользователь не переходит на отдельный URL с формой: содержимое одного диалога меняется по состоянию. Поэтому белая форма — отдельный шаг интерфейса, но не отдельный серверный маршрут.

`bookingMovie = null` закрывает весь сценарий. `setBookingStep('seats')` возвращает к выбору мест. При начале новой брони `openBooking` очищает старые ошибки и выбранные места, чтобы случайно не перенести выбор другого сеанса.

Учитывай различие между `detailMovie` и `bookingMovie`. Первый открывает описание фильма, второй — бронирование. В `openBooking` описание закрывается через `setDetailMovie(null)`, затем открывается нужный фильм и время.

Если преподаватель спрашивает «где переход между страницами», покажи изменение `bookingStep`. Не надо искать несуществующие файлы `checkout/page.tsx` или `success/page.tsx`: сейчас их нет.

## 9 Ключ сеанса и загрузка занятых мест

Функция `getShowtimeKey` собирает фильм, дату, время и город в одну строку. Например:

```text
batman-1989|2026-10-27|17:00|tallinn
```

Без даты и времени бронь на один показ могла бы ошибочно занимать такое же место на другом показе. Вертикальная черта здесь просто разделитель. Строка не является паролем или секретным токеном.

`openBooking` — асинхронная функция. Сначала она устанавливает состояния окна и загрузки, затем выполняет GET. `encodeURIComponent` кодирует ключ для безопасной передачи как значения query-параметра. `await response.json()` читает тело ответа, а `response.ok` проверяет успешный HTTP-статус.

```ts
const response = await fetch(
  '/api/bookings?showtimeKey=' + encodeURIComponent(key)
);
const payload = await response.json();
```

Это сокращённая иллюстрация; в реальном файле ключ создаётся вызовом `getShowtimeKey(movie, time)`. Если запрос успешен, массив `occupied` попадает в `unavailableSeats`. Если запрос не удался, показывается ошибка; блок `finally` выключает состояние загрузки.

Серверный GET берёт `showtimeKey` из URL и делает SELECT по `booking_seats`. К результату добавляются заранее заданные демонстрационные занятые места `systemOccupiedSeats`. Поэтому часть мест занята даже в пустой базе — это не обязательно реальные пользовательские брони.

Важное ограничение: при ошибке загрузки интерфейс всё ещё показывает сообщение, но не является полноценной системой резервирования. Сервер повторно проверяет места при POST. Для реального продукта стоило бы полностью блокировать продолжение при недоступной схеме и добавить явную повторную загрузку.

## 10 Как работает выбор мест

Открой `toggleSeat`. Первый `if` запрещает менять занятое место. Далее применяется функциональная форма setter, чтобы работать с актуальным состоянием, а не со старым значением из предыдущего рендера.

```ts
setSelectedSeats((current) =>
  current.includes(seat)
    ? current.filter((item) => item !== seat)
    : [...current, seat]
);
```

Если место уже есть в массиве, `filter` создаёт новый массив без него. Если места нет, spread `...current` копирует старые элементы и добавляет новый. Существующий массив не изменяется через `push` или `splice`.

Ряды задаются массивом `['A', 'B', 'C', 'D', 'E', 'F']`. Внутри каждого ряда `Array.from({ length: 10 }, ...)` создаёт подписи от A1 до A10 и так далее. Всего на схеме 60 мест. Занятое место получает `disabled`; выбранное окрашивается по проверке `selectedSeats.includes(seat)`.

Сумма на экране вычисляется как количество мест, умноженное на `bookingMovie.price`. `toFixed(2)` нужен для отображения двух знаков после запятой. Это строковое форматирование, а не способ хранения цены в базе.

Кнопка продолжения отключена, когда не выбрано ни одного места или идёт загрузка. Сервер отдельно допускает не больше десяти мест на одну бронь. В текущем интерфейсе пользователь может выбрать больше десяти и получить отказ при отправке: клиентское ограничение количества — понятная будущая доработка.

Упражнение: выбери A1, добавь A2, сними A1 и объясни содержимое массива после каждого действия. На сервер при подтверждении должен уйти только A2. Затем открой другой сеанс: предыдущий выбор должен очиститься.

## 11 Белая форма и отправка заказа

Форма специально оформлена просто. Её внешний вид задают `.checkout-dialog` и `.plain-checkout` в `app/globals.css`. Используются обычные HTML-поля `input`, а не отдельная система регистрации. Подпись имени берётся из `c.name`, пример внутри поля — из `c.namePlaceholder`, сейчас это Timo Triisa.

`required`, `type="email"`, `minLength` и `maxLength` дают базовую проверку браузера. Пример имени — placeholder, он не отправляется, если поле пустое. На защите обязательно введи имя сам.

```ts
event.preventDefault();
const formData = new FormData(event.currentTarget);
```

`preventDefault()` останавливает обычную перезагрузку страницы при отправке формы. `FormData` читает поля по атрибуту `name`: `formData.get('name')` и `formData.get('email')`. Наличие красивого текста возле поля не заменяет этот атрибут.

`submitBooking` отправляет POST с заголовком `content-type: application/json`. В JSON входят ключ сеанса, фильм, дата, время, имя, email и массив мест. Итоговую цену браузер не отправляет; сервер считает её сам.

Пока запрос выполняется, `bookingSubmitting` отключает кнопку. Это уменьшает риск случайного двойного клика, но не является полноценной защитой от повторного HTTP-запроса. Для промышленной версии нужен идентификатор идемпотентности.

Успешный ответ содержит `booking.reference`. Он записывается в `confirmationId`, а `bookingStep` меняется на `success`. При конфликте сервер может вернуть список новых занятых мест; страница добавляет их в `unavailableSeats`. Текущая обработка ошибки общая: она не всегда объясняет точную причину и не очищает автоматически конфликтный выбор.

## 12 Серверные проверки и HTTP ответы

Открой `app/api/bookings/route.ts` и найди `POST`. Сервер сначала пытается разобрать JSON, затем очищает строки через `trim`, приводит email к нижнему регистру и убирает дубликаты мест с помощью `new Set`.

```ts
const seats = Array.from(new Set(body.seats || []));
const seatPattern = /^[A-F](10|[1-9])$/;
```

Регулярное выражение разрешает букву A–F и номер от 1 до 10. Например, A1 и F10 проходят, G1 и A11 не проходят. Ограничения: имя от 2 до 80 символов, email подходящего формата, от одного до десяти корректных мест. Также нельзя выбрать заранее занятое демонстрационное место.

| Статус | Что означает в этом проекте |
| --- | --- |
| 200 | Получение данных прошло успешно |
| 201 | Бронь создана |
| 400 | Некорректные или неполные данные |
| 404 | Фильм не найден при расчёте цены |
| 409 | Место занято или возник конфликт уникальности |
| 503 | База или операция временно недоступна |

Для SELECT и INSERT используются `prepare` и `.bind(...)`. Значения передаются отдельно от SQL, что защищает именно эти параметры от подстановки SQL-кода. Список вопросительных знаков в `IN (...)` создаётся по количеству мест; сами значения всё равно передаются через `bind`.

Не преувеличивай качество проверки: приведение `as BookingInput` не защищает от произвольных типов JSON. Некоторые ошибочные типы могут вызвать исключение до общего блока работы с базой. Кроме того, сервер пока не сверяет целиком комбинацию даты, времени и ключа с разрешённым расписанием. Это учебный backend, а не готовая публичная касса.

## 13 База и защита от двойного бронирования

В базе две основные таблицы. `bookings` содержит одну запись на заказ: идентификатор, номер брони, имя, email, дату, время, сумму и статус. `booking_seats` содержит отдельную запись на каждое место. У брони на три места будет одна запись в первой таблице и три во второй.

```sql
CREATE UNIQUE INDEX booking_seats_showtime_seat_unique
ON booking_seats (showtime_key, seat);
```

Уникальный индекс запрещает два одинаковых сочетания сеанса и места. Это важнее, чем только предварительный SELECT. Два посетителя могут загрузить свободную схему одновременно; при записи база должна остановить вторую бронь на то же место.

До записи выполняется проверка конфликтующих мест. Затем `d1.batch` объединяет INSERT брони и INSERT выбранных мест. Операции D1 batch выполняются последовательно транзакционно: при ошибке пакет откатывается. Проверка уникальности остаётся необходимой для конкурирующих запросов.

В `db/index.ts` функция `ensureDatabase` создаёт таблицы и индексы через `CREATE ... IF NOT EXISTS` при обращении к данным. Это упрощает локальный запуск без отдельного ручного импорта SQL. Для большого приложения повторную подготовку схемы при каждом запросе обычно заменяют контролируемыми миграциями.

`db/schema.ts` описывает те же сущности через Drizzle. Но обработчик бронирования сейчас работает напрямую с D1 через SQL; он не вызывает `getDb()`. Если преподаватель спросит «где ORM», покажи описание схемы и поясни, что в основных запросах использован прямой SQL.

Цена хранится в `total_cents` целым числом. Умножение 7 евро на два места даёт 1400 центов на сервере. В базе отсутствует таблица пользователей, потому что бронь гостевая. Email не является подтверждённой личностью посетителя.

## 14 Даты язык стили и дополнительные маршруты

`getShowDates` находится в `lib/show-dates.ts`. Функция берёт текущий календарный день в часовом поясе Europe/Tallinn и создаёт семь записей. У каждой есть отображаемые `day` и `date`, а также технический `key` вида `2026-10-27`. Перевод названия дня не меняет ключ бронирования.

Вычисление через `Date.UTC` использует полдень, чтобы избежать случайного перехода даты из-за часового пояса при форматировании. Проверять нужно не только обычный день, но и границу месяца и момент, когда в Таллинне уже наступили следующие сутки.

Язык сохраняется в `localStorage` под ключом `lumen-locale`. Там хранится только настройка интерфейса, а не бронь. Второй `useEffect` обновляет `document.documentElement.lang` и сохраняет выбранное значение. При открытии страницы первое состояние английское, затем читается сохранённая настройка. Для реального приложения такую инициализацию можно дополнительно улучшить.

В `app/globals.css` заданы общие цвета, сетка карточек и media queries. При уменьшении ширины число колонок становится меньше. В белой форме свои правила переопределяют тёмную тему. Глобальные правила отключают CSS-анимации и переходы; переключение экрана происходит сразу.

`GET /api/health` выполняет простой запрос к базе и возвращает `database: connected` либо ошибку 503. Это проверка доступности, а не мониторинг всех функций.

`GET /api/catalog` формирует дополнительный JSON со списком фильмов и сеансов. В текущем коде у него осталась фиксированная дата по умолчанию и иной формат `showtimeKey`, чем у страницы. Главная его не использует. Это конкретная задача на согласование API, которую можно назвать при обсуждении дальнейших улучшений.

## 16 Вопросы преподавателя и короткие ответы

### Где хранится список фильмов

В массиве `movies` файла `lib/catalog.ts`. Это исходные данные проекта, не таблица фильмов в базе. База нужна для бронирований и занятых мест.

### Почему используется TypeScript

Он помогает проверять форму данных и допустимые значения во время разработки. Например, язык ограничен `en`, `ru`, `et`. Он не заменяет проверку HTTP-запроса на сервере.

### Что произойдёт при обновлении страницы

Текущий выбор мест и шаг формы могут сброситься, поскольку это состояние React. Уже созданная бронь останется в локальной базе. Выбранный язык сохраняется отдельно в `localStorage`.

### Можно ли купить настоящий билет

Нет. Это демонстрационное бронирование без оплаты. Постеры настоящих фильмов не означают реальное расписание кинотеатра.

### Почему email не означает регистрацию

Поле записывается в контактные данные конкретной брони. Нет пароля, подтверждения почты, сессии пользователя и таблицы аккаунтов.

### Как обрабатываются два человека на одном месте

Есть предварительная проверка и уникальный индекс на `(showtime_key, seat)`. Даже если два человека увидели свободное место одновременно, вторая конфликтующая запись не должна пройти.

### Откуда берётся итоговая сумма

В браузере она показывается по цене фильма и числу выбранных мест. При сохранении сервер снова находит цену в каталоге и считает сумму в центах.

### Что будет если база недоступна

Сервер возвращает ошибку, интерфейс показывает сообщение. Это не успешная бронь. Надёжную повторную отправку и более подробную диагностику ещё можно доработать.

### Какие части проекта пока незакончены

Нет оплаты, писем, отмены брони, интерфейса администратора и полноценного управления сеансами. Обработка некоторых ошибок и согласование дополнительного API каталога требуют улучшения.

### Почему несколько операций на сервере

Нужно записать сам заказ и все его места. Если сохранить только заказ без мест, другие посетители увидят их свободными. Поэтому INSERT объединены в один пакет.

### Что такое компонент и состояние

Компонент — функция с JSX. Состояние — изменяемые данные, которые влияют на интерфейс. Например, смена `activeGenre` приводит к новому списку карточек.

### Что означает await

Функция ждёт завершения асинхронной операции, например ответа HTTP. Это не замораживает весь браузер. Состояния загрузки позволяют объяснить пользователю, что запрос ещё выполняется.

### Зачем нужны ключи у карточек

`key={movie.id}` помогает React сопоставлять элементы при фильтрации. Индекс массива хуже подходит, когда список меняет порядок или состав.

### Можно ли обойти проверки браузера

Да, HTTP-запрос можно отправить напрямую. Поэтому сервер проверяет основные данные повторно. В учебной версии проверки типов входного JSON ещё не полностью защищены от произвольного запроса.

### Что означают коммиты

Они показывают сохранённые тематические наборы файлов и последующие изменения. При переносе уже готовой локальной версии их порядок не доказывает первоначальные сроки разработки. Объясняй содержимое конкретного коммита, если об этом спрашивают.

Для дальнейшего самостоятельного изучения используй официальные документы React, TypeScript, MDN по fetch и FormData, Cloudflare D1 по SQL и batch. Этот документ объясняет текущую реализацию; при изменении кода отдельные детали и имена функций нужно проверять заново.

Последняя проверка перед защитой: я могу показать путь пользователя, объяснить ключевые функции, назвать ограничения и предложить одну полезную доработку с оценкой времени.
